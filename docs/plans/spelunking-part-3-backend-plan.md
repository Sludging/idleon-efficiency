# Spelunking Part 3: backend delivery plan

## Outcomes

Deliver backend data for [#437 — Amber, equipment, and advanced progression](https://github.com/Sludging/idleon-efficiency/issues/437):

- Show account Amber and shop upgrades with saved levels, caps, unlock requirements, and intrinsic effects.
- Keep tool identities/stats and automatic-use account setting/eligibility available from their existing data APIs when another consumer needs them. Current UI has no Tools/AUTO section. Never infer saved current-tool/team selection or active AUTO run; those are actor-local.
- Show indexed Elixir descriptions alongside owned count, saved memorized IDs, equipped slots, and limits. Do not infer names or structured effects from descriptions.
- Show read-only Manic, Overstim, and Trackometer saved progression, gates, thresholds, and effects. Do not simulate refill overflow or mode progression.

This plan extends existing Spelunking data. Preserve accepted Part 1 Amber-haul denomination/formatting and Part 2 stamina/recharge/Trackometer maximum-stamina behavior. Do not add authored player-facing descriptions, an efficiency calculator, or an independent Amber/shop owner.

`Upgrade.getBonus()` supplies `ShopUpgBonus(index, 1)` and `getEffectiveBonus()` currently supplies only the accepted Manic and Trackometer scaling. `Spelunking.getTotalDiscoveries()` and `manic.totalDepth` supply discovery count and Manic depth. Existing `Tunnel.bestDepth` and `biggestHaul` supply their saved source inputs. The current domain does not expose the rest of the caller's source values.

Add named, source-specific prepared values to `Spelunking` and its existing `Upgrade` owner; do not add a generic marker/description framework. Required inputs and outputs are:

- Sum nonnegative Player Spelunking skill levels once. Use it for `ShopUpgBonus(0,0)` and `^` at index 8.
- Sum Tunnel best depths for `^` and the source totals at indices 2 and 9. Sum `ceil(getLOG(Tunnel.biggestHaul))` for `^` and index 3's total. Use `getTotalDiscoveries()` for indices 1 and 10.
- Prepare source mode-0 totals: index 0 is owned bonus × all-player skill-level total; index 8 is owned bonus × `(1 + skill-level total / 100)`; indices 1 and 10 multiply owned bonus by `1 + 5 × discoveries / 100`; index 2 by `2 + best-depth total / 100`; index 9 by `1 + best-depth total / 100`; index 3 by `1 + 3 × biggest-haul digit total / 100`; indices 54–56 by `1 + 5 × Manic depth / 100`; indices 59–61 by Trackometer level. Reuse existing `Upgrade.getEffectiveBonus`/`Spelunking.getEffectiveUpgradeBonus` where applicable.
- Preserve source's special bonus outputs at indices 7 (`15 + owned / (250 + owned) × 45`), 19 (`max(10, 50 - owned)`), 21 (`1 + 7 × owned / 100`), 25 (`1 + owned`), 38 (`20 + owned`), and 44–46 (owned bonus × Grand Discovery total). Reuse the existing Grand Discovery count.
- Prepare source caller's non-bonus outputs: Exalt and Prisma reciprocal-chance denominators plus their saved drop-depth counters at 27/28; best unlocked tool name and power at 40. Parse `Spelunk[4][3]` and `[4][4]` as the saved account drop-depth counters. The source description's `#` displays the corresponding saved “found so far” counter; preserve it independently from the actor-local session counter. The original helper's chance is probability `p = (1 + owned bonus / 100) / (base × factor^savedDepth)`, while the intrinsic `1 in $` description requires denominator `1/p = base × factor^savedDepth / (1 + owned bonus / 100)`: Exalt uses base 60 and factor 8; Prisma uses base 100 and factor 1.5. The original exponent adds actor-local `_GENINFO[88]`/`[89]`; account-only values omit only that session addend and retain saved depth and owned chance factor. For source comparisons, Exalt saved depth 1 and owned bonus 100% gives probability `1/240`, rendered as `1 in 240`; Prisma saved depth 2 and owned bonus 50% gives probability `1/150`, rendered as `1 in 150`. These are source-helper comparisons with session addend zero, not current-delve chance claims. Index 40 uses saved upgrade unlocks and existing tool metadata. `AmberGain` uses actor-local state but no current upgrade description consumes its `$` output; it is out of display scope. Index 43's current-character chance is outside the account-only display; its source description retains the non-numeric chance wording and per-tunnel limits.

Run this Spelunking preparation once after Player, tunnel, Manic, Trackometer, and discovery inputs are ready. Keep save parsing free of cross-domain reads.
