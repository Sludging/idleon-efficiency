## Outcomes

- Expose imported-account unlock state and verified saved progression for Purple, Blue, Red, Silver, Yellow, and Green in Menagerie.

- Preserve Part 1's existing Purple/Yellow contribution to Lumi/hour and all other current integrations. Add no cross-system effect wiring or recipient calculations.
- Expose only player-facing names and descriptions supplied by static game data. Add no authored mechanic descriptions or inferred copy.

## Scope decision

The historical Part 2 draft included recipient integrations. The current request explicitly defers new cross-system effect integrations and preserves current integrations without expansion. No human decision is needed on this boundary.

## Integration and prerequisites

- Preserve the accepted Part 1 `Menagerie` save mappings, typed Lumi inputs, and current `LumiGainRate` calculation. Purple and Yellow panels report those same inputs; they must not recalculate or apply them twice.
- Keep all other current `postProcessingMap` consumers and order unchanged. Part 2 adds no Blue-to-Cooking, Red-to-Spelunking, Silver-to-Obols, or Yellow-to-Construction recipient wiring, and creates no new recipient systems. Existing Jelly Operator/Spelunking behavior remains untouched.
- Keep side-jelly behavior in Menagerie-owned methods and typed state. Use current domain APIs for any required external account values; do not reparse another domain's save fields. Preserve `init` → `parse` → ordered `calculate` boundaries, and place any UI-only derived presentation after its inputs are ready.
- Generated prerequisites already present: `MenagerieJellyfishRepo.ts` provides panel identities, Purple Money and upgrade rows, Blue Ladle, Silver Obol Fragments and caps 100/190, Yellow effect coefficients 25/15/10/3, and Green item IDs/count 12. `MenagerieUnlockRepo.ts` provides unlock records. `ItemDetailRepo.ts` names `EquipmentNametag28` “Tome Legend Nametag.” Relevant shapes are `menagerieJellyfishModel.ts`, `menagerieJellyfishCurrencyModel.ts`, `menagerieJellyfishUpgradeModel.ts`, and `menagerieJellyfishRewardModel.ts`.
- Existing generated data supplies all required static values. `../IdleonWikiBot/exported/ts/data/MenagerieMissionRepo.ts:7–15` and `data/domain/data/MenagerieMissionRepo.ts:7–15` expose source-indexed `initialRequirement`/`requirementIncrement` for mission requirements; native `Cost` at `idleon1.23.txt:118743–748` consumes them for missions, not Purple Jellyfish. Purple costs use separate `PinkJellyCosts` at `118838–842`; no WikiBot/static-data prerequisite remains.
- Yellow's saved progress is the selected output; do not calculate a rate from unlabeled `GenINFO` inputs. Yellow unlock ownership gates Construction-loop progress, not slot-8 occupancy. Purchases preserve saved progress; the reset clears levels only. Preserve existing Purple/Yellow Lumi inputs without applying either twice.
- No new Blue/Cooking, Red/Spelunking, Silver/Obol, or Yellow/Construction wiring is permitted. Preserve existing Part 1 Lumi inputs and all current integrations. Existing Jelly Operator/Spelunking behavior remains untouched.
- Static catalog labels are record identifiers, not verified verbatim game descriptions. Expose descriptions only when supplied by static data, as required by scope.
