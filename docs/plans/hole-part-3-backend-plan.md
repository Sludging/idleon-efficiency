## Required data and prerequisites

- Direct 1.22 source maps cavern IDs `1, 7, 11, 16` to requirement indices `0..3`. `Holes[0][playerIndex]` stores each character's cavern assignment. Current resource is `Holes[11][2*i]`; claim increments progression at `[11][1+2*i]`; completed count is `Holes[7][cavernID]` [`260405-260439,262341-262418,266057-266061`]. Lifetime ore is `Holes[11][32]`: collected drop amount increments it for the Motherlode resource type, without conversion [`188497-188504`]. `B_UPG(58)` consumes this total as `5 * log(total)` [`239376-239377`].
- Let `layerState = Holes[11][1+2*i]`. `TotalOreREQ(i)` is `(1 + 99*floor(i/3)) * 200 * 2.2^(1 + layerState) / (1 + reductions/100)`. `reductions` sums Jar collectible 5 and Study bonuses 1, 7, 11, and 16 multiplied by progression at `[11][1,3,5,7]` [`239606-239617`]. `MotherlodeEffBase(i)` is `20,000 * (1 + 99*floor(i/3)) * 1.8^(1+layerState)`; displayed threshold is `0.25 * base` [`239618,260448-260459`].
- The caller selects the assigned character's Mining, Catching, Choppin, or Fishing efficiency. It compares that value with `0.25 * MotherlodeEffBase` for display styling only; capability does not gate progress or claim [`260448-260459,262343-262349`]. The 1.22 producer bodies and their source inputs are cited under Responsibilities.
- A claim requires current resource `>= TotalOreREQ` and shared `OptionsListAccount[318] < 6`; it increments the counter, clears current resource, advances paired progression and completed count, then refreshes available Opals [`262343-262418,262483-262492`]. `OpalsOwnedToInvest` reads `_GenINFO[69]`; the event calculates it as fixed bonus sources plus `sum(Holes[7]) - sum(Holes[3][0..7])`. The daily branch resets `[318]` to zero when `[315] == 0` [`319316-319327`]; source does not establish the trigger time. Wiki revision 103837 says five claims per day. Preserve source-six versus Wiki-five and do not assert a maximum, remaining allowance, or claim availability yet.
