# Spelunking Part 3 UI plan

## Player outcome

Show Amber shop progression, tools and elixir state, and advanced progression in three direct sibling views beside **Tunnels** and **Journal & Pages**. Keep the shared account summary and character grid above the views. Do not add a “Part 3” label or nested Part 3 selector. Preserve existing Tunnels and Journal content and their local filters.

## View composition

- **Shop:** Keep one compact aligned table: upgrade, saved level/cap, prerequisite, and named effect with its source-backed value. At the 1440px preview, allocate columns at **21 / 12 / 22 / 45%**; use the current shell width and no duplicate page inset. Use small game icons beside upgrade names. Keep locked rows visible by default and preserve the existing filter. Show each owned effective bonus from the accepted backend beside its effect identity. For an unowned level-based upgrade, show the static `bonusPerLevel` contribution as **Per level**, paired with its source-defined effect name and unit; do not present that value as an owned total or calculated purchase outcome. Do not label values “Prepared bonus value.” Keep unsupported next prices and affordability omitted.
- **Equipment:** Restore the prior compact tool table, with columns for tool, stamina, hit radius, damage multiplier, and availability; use proportional widths **19 / 14 / 16 / 19 / 32%**. Use `CaveShopUpg14.png`–`CaveShopUpg17.png` only for Mace, Mallet, Flail, and Warhammer. Leave other tool imagery unassigned. Keep source-defined **Unavailable** for Scepter and Mjolnir. Keep full-clear state separate from AUTO eligibility. Show shared elixir limits once. List all twelve intrinsic descriptions in one readable, full-width list. Label equipment slots starting at **1**; label memorization separately. Convert `@` layout separators to spaces and each unexported quantity marker to `?`. Explain `?` once beside Elixirs. Do not invent names or quantities, or show raw control markers.
- **Advanced:** Use three top-aligned groups with content-driven heights; never stretch short Overstim content to Manic’s depth-list height. At 1440px, use proportional columns **1.15fr / 0.8fr / 1.05fr**, **12px** gaps, and group height from each group’s own content. Show each saved state, level, fill/threshold, and **6px** progress meter once. Pair each known effect with its exact backend value and identity: all three Manic effects, Overstim’s Amber per-level bonus and gain multiplier, and all three Trackometer totals plus their per-level contributions. Keep a known per-level value visible when its current total is zero. Use Manic depth records under canonical tunnel names. Keep unresolved intrinsic source wording as secondary detail; convert unknown quantities to `?` and explain once in this view. Never assign a marker to a prepared value without proven caller mapping.

## Source and presentation decisions

The offline v1.22 `ShopUpgVisible` caller uses saved prerequisite level `>= 0`; this means prerequisite level 0 is purchased. Only entry 0 has no prerequisite. A `requiredUpgrades` value of 0 is a real prerequisite on other entries. Evidence: `docs/game-snippets/spelunking/Spelunk.1.22.js:8`, `data/domain/model/spelunkingUpgradeModel.ts:10`, and `data/domain/data/SpelunkingUpgradeRepo.ts`.

The targeted original-caller follow-up is [`spelunking-part3-inline-marker-followup.md`](../../.omp/research/spelunking-part3-inline-marker-followup.md). It confirms `ShopUpgBonus(index, 1)` as base `bonusPerLevel` multiplied by saved owned level; mode 0 is the effective owned bonus after source adjustments. For Manic, indices 53–55 identify POW, Grand Discovery Chance, and Spelunking Efficiency; effective values use the saved Manic-depth multiplier where applicable. For Trackometer, index 59 identifies Stamina EXP Gain, index 60 Amber Gains, and index 61 Max Stamina in generated intrinsic descriptions. Each total uses its owned upgrade bonus multiplied by saved Trackometer level. Show owned bonus per Trackometer level, not static purchased-upgrade-level potential. Original UI callers render advanced helper outputs separately. No inspected original shop formatter or caller proves `{`, `^`, `$`, or `@` substitutions, argument order, branch behavior, or unowned purchase potential. Therefore, never align a source-text marker with a bonus value.

Use static effect names and `bonusPerLevel` metadata plus accepted backend `getBonus()` / `getEffectiveBonus()` values for the main effect row. Keep original intrinsic text as secondary source-text detail, replace unresolved quantity markers with `?`, and render `@` as spacing. Explain `?` locally once per view. Preserve literal signs, wording, and source units; do not derive values from text or add unverified units. Elixir quantities remain unexported; retain their intrinsic wording with `?` only at missing quantities. This display makes no original-game-formatter parity claim.

The UI consumes the accepted Part 3 backend and existing static records. It adds no backend behavior, authored descriptions, exports, calculations, progression simulation, current shop prices, or inferred run selections. The preview shows representative source-backed rows and one retained unpaired save’s displayed state. It is not connected-game parity or production approval.
