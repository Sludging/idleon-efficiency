## Player mechanic and useful outcome

Gallery stores account-wide trophy shelf/podium placements and nametag deposits. Each character has a separate Gallery portal unlock state and trophy-chip contribution, so shared deposits can produce character-specific multiplier results. The domain parses `Spelunk[16]` placement slots and `Spelunk[17]` nametag counts; 48 trophy shelf positions precede podium positions [`gallery.tsx:110–143`](../../data/domain/world-7/gallery.tsx#L110). Podiums expose availability and tiers 1–4; saved overflow placements remain represented, while availability does not gate their contribution [`gallery.tsx:31–38,201–210`](../../data/domain/world-7/gallery.tsx#L31).
The player-facing [Gallery Wiki page](https://idleon.wiki/wiki/The_Gallery) (revision `oldid=103596`, edited 2026-10-07) describes permanent deposits with Codfrey in Shimmerfin Grove, display-slot placement for trophies, and account-wide bonuses. It describes nametag bonus scaling by copies deposited, up to five, rather than a separate saved level. It names trophy effect tiers as Tier 0 (30%), Tier 1 (100%), Featured (150%), Masterpiece (200%), and World Class (250%). Wiki notes its information may be incomplete.
The captured v1.22 game formula represents shelf trophies at `0.3 × multiplier`; podium tier multipliers are 1, 1.5, 2, and 2.5. Nametag copy scaling is represented by `stackMultiplier` in Gallery [`Gallery.1.22.js:65–81`](../game-snippets/gallery/Gallery.1.22.js#L65), [`gallery.tsx:40–48`](../../data/domain/world-7/gallery.tsx#L40). The Wiki's tier labels and in-domain numeric tiers are not a one-to-one named mapping in available evidence; avoid assigning those names to numeric tiers without further verification.
Exact in-game interaction steps, item acquisition requirements, reclaim behavior, and meanings of “listed” versus “owned” are not established by this Wiki/source evidence.
`Gallery` does not represent named trophy inventory ownership separately from deposits: its count increments from placement slots. A nametag count is saved deposit count, not an independently modeled level [`gallery.tsx:23–29,117–140`](../../data/domain/world-7/gallery.tsx#L23).

A useful read-only page lets players inspect where each trophy is deposited, see podium availability and grade distribution, compare the trophy and nametag collections, and understand bonus outputs for account-shared deposits across specific characters. It must distinguish shared deposit state from character-specific bonus scaling and must not imply a website action changes the game save.

## Existing coverage and public API boundary

`Gallery` is initialized and its contribution updater runs after settled dependencies [`idleonData.tsx:126,212,375–376`](../../data/domain/idleonData.tsx#L126). It initializes trophy/nametag records and effect inputs from `Item` definitions [`gallery.tsx:74–107`](../../data/domain/world-7/gallery.tsx#L74), parses placements and nametag counts [`gallery.tsx:110–143`](../../data/domain/world-7/gallery.tsx#L110), and computes podium tier/capacity and per-player effects [`gallery.tsx:169–240`](../../data/domain/world-7/gallery.tsx#L169).

**Acquired means deposited, not bag inventory ownership.** Local competitor parser [`gallery.ts`](../../reference-repos/IdleonToolbox/parsers/world-7/gallery.ts) derives trophy acquired state from occupied Gallery placements and nametag state/count from `Spelunk[17]` (lines 377–401, 463–518); lines 126–179 use the first 48 `Spelunk[16]` entries as shelf slots and later entries as podium placements. Its `inventoryTrophies` name means shelf display, not bag inventory. Our parser independently matches: `GalleryTrophy.count` increments for placements, `obtained` is `count > 0`, and nametag `count` comes from `Spelunk[17]` [`gallery.tsx:23–29,110–143`](../../data/domain/world-7/gallery.tsx#L23). Model page states as **deposited / not deposited**, not owned / inventory-missing; no inventory ownership expansion.

Current state API: `trophies` provide `count`, `obtained`, `index`, `internalName`, `name`; `shelves` provide ordered occupied/empty slots; `podiums` provide `trophy`, `available`, `tier`, and numeric `multiplier`; `nametags` provide `count` and numeric `stackMultiplier` [`gallery.tsx:23–48,51–59`](../../data/domain/world-7/gallery.tsx#L23). `isUnlocked(player)` is character-specific. `getTrophyBonus(effect, player)` and `getNametagBonus(effect, player)` provide numeric per-player effect values; `getTrophyProperty(property, player)` and `getNametagProperty(property, player)` provide numeric property values, gated by that player's unlock [`gallery.tsx:61–65,145–165`](../../data/domain/world-7/gallery.tsx#L61). Do not calculate these again in UI.

**Backend API boundary:** Gallery remains the calculation owner. Reuse existing collection, placement, deposit-count, and numeric bonus APIs. Add only exact available podium-tier counts, the character-specific multiplier, and the combined unlocked effect; expose no mutable bonus map or UI read model. Do not promise an account-wide “Bonus Multiplier” because its player semantics are unverified.

Static item metadata prerequisite is limited to records the selected page consumes: each trophy/nametag definition and effect channel for displayed entries, since initialization builds those lists from `Item` and missing definitions throw when referenced [`gallery.tsx:74–107,121–123,133–138`](../../data/domain/world-7/gallery.tsx#L74).
