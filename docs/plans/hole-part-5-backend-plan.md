## Outcomes

- **Jars:** Represent saved board work, reward state, collectible levels, and holdings with source-backed current effects.
- **Fountain:** Represent saved stack/upgrade/Opal state and current valuations without forecasting production or random outcomes.
- **Crystal Glunko Cove:** Represent saved shapes, purchases, and gated character-local benefits without conflating them with ordinary account stats.

All outputs describe imported state or verified current-state calculations. Do not advance production, simulate rolls, extrapolate snapshot values, or add forecasts. Expose game descriptions only from static data; do not author new player-facing descriptions.

- **Jars:** Ten types use `HoleJarRepo` indices 0–9. Saved `Holes[11][37]` is an owned-type **count**, and new-type purchase stops at count 9; index 9 is the tenth type record, not the stopping count. New types cost `50 × (1+n)^1.5 × 4.8^n` from `Holes[9][20+n]`. Production starts at 11 owned caverns and uses one, two, or three producers from camp upgrades 63 and 66. Each producer adds `JarProductionPerHR × elapsedSeconds / 3600` to `Holes[25][producer+3]`; `Holes[25][producer]` selects requirement `(1000 + 2000×type)/((1+B_UPG(67,30)/100)×(1+B_UPG(74,5)×gameLOG(Holes[11][max(0,type−1)+40])/100))`. The base hourly rate is 36,000 × `(1+(collectibles 1+15+24+Measurement 12)/100)` × `(1+B_UPG(72,10)×gameLOG(Holes[11][38])/100)`, where `gameLOG(x)=Math.log(Math.max(x,1))/2.30259`. The saved `Jars` board entries persist type, quality, x/y position, and random roll; each entry is five values, with a 120-entry total board limit. Runtime actor images are transient and are not imported as saved state. Quality is `floor(log10(work/requirement))`. Work is not currency and only pays when collected. Types 0, 3, 5, 6, 8, and 9 give random currency rewards; types 1, 2, and 4 trigger Opal, discovery, and enchantment chances. Type-1 Opal chance is `0.25 × 0.43^Holes[7][10] × (1+Collectible2/100) × (1+Collectible14/100) × (1+Collectible27/100)`. Rupie balances 0–9 are `Holes[9][20..29]`; special currencies 10/11 are `Holes[11][38]/[39]`. Type 0 tier thresholds are 100/1,000, type 3 are 10,000/500,000, and type 6 are 6,000,000/50,000,000; types 5 and 8 give IDs 10/11. Each opened jar can roll `floor(1+JarRupieExtraChance+randomFloat)` currency events. Quality multiplies rupie value and each chance by `10^quality`. Type-7 Gilded Jars double the next jar reward; do not promise random break order. Rupie value includes Hole upgrades, account option 355, Lamp, Monument, Measurements 10/14, Hole progress, Collectibles, Cavern-resources Stamp, and Cove upgrade 14. - **Collectibles and enchantments:** `Holes[24][0..39]` stores levels: zero is undiscovered, one is discovered, and higher values retain repeat enchantments. The 40 indexed static records supply names, descriptions, and coefficients in `HoleJarBonusRepo[i].data.bonus`; each coefficient matches `parseFloat(CustomLists.HolesInfo[67][i].split('|')[1])` in v1.23. The game scales saved level by that coefficient and Legend Points bonus 29. Enchant chance is `0.35/(1+n^1.23+1.1^n)` times bonuses from Collectibles 9/18/26/34, camp 73 and `gameLOG(Holes[11][39])`, Study 10, and Fountain 2/15; `n` sums each level above one. Quality multiplies the roll threshold by `10^quality`. `Holes[11][62]` stores the preferred target. When Study 10's owned rule applies, it replaces a random eligible target with the preferred discovered target at chance `5/(eligibleCount+3)`; it does not guarantee selection. Without B_UPG 75, discovery/enchantment candidates are limited to indices 0–15; B_UPG 75 opens all 40. - **Fountain:** Wallets are `Holes[9][30..38]`; each pending position is an item-ID array in `Holes[29][space]`, including empty arrays, and its royal flag is `Holes[34][space]`. Position occupancy counts non-empty item arrays; item count sums each array length. Capacity is `min(16,1+Fountain_BonTOT(0,10))` positions; each position holds at most `min(50,3+B_UPG(97,3)+Fountain_BonTOT(0,11)+CosmoBonusQTY(4))` items. Selected desire is `Holes[11][82]`; `Holes[11][83]` encodes excluded generated currencies with `Number2Letter` markers, and generation falls back to currency 0 if exclusions remove all candidates. `Holes[30][currency]` is lucky-coin count, not a stack. At claim, the game iterates every currency ID in each position and credits its current currency value times `(1+positionItemCount×B_UPG(95,10)/100)`; a royal flag adds `max(1,RoyalMulti−1)` times that item's current value with the same factor. Empty positions contain no items to claim. When no position has room, generation immediately credits `currencyValue×Fount_CurrencyKEEP`, where `KEEP=0.1+(Fountain_BonTOT(0,8)/(100+Fountain_BonTOT(0,8)))×0.5`; this overflow is not a pending stack. Stack values use current levels and modifiers at claim, not saved snapshots. `Holes[11][7]` is an unnamed saved exponent input in `max(1,B_UPG(94,1)×1.1^value)`; v1.23 evidence does not establish a player-facing name. ## Integration

Follow `init → parse → calculate`. Initialize existing Jar/Fountain records and Cove's RandoList2 mapping under Hole. `Hole.parse` delegates raw `Holes`, `Jars`, and `OptionsListAccount` values to typed aspect parsers; Study 17 retains ownership of the existing saved counter at option 604. Parse must not read other domains or calculate effects.

Extend Hole-owned update orchestration, not the account-domain registry with a second Hole. Existing `holeStudyEffects` and `holeUpgradeEffects` hooks prepare shared Hole effects before consumers. The `hole` post-processing key in `data/domain/idleonData.tsx:350` runs after Legend Talents, Gaming, Farming level, Tome, and Deathnote producers. Keep parsing raw-save-only.

Within Hole calculation, derive saved-only Fountain upgrade effects and Cove account upgrade values first; Fountain's 60 indexed upgrades and Cove's 24 saved levels do not require runtime or character selection. Prepare Measurements and Jar bonus/rate outputs with their required Fountain upgrade, Legend Points 29, Study 10, and account inputs. Then prepare Bell, which consumes Jar bonuses and Measurement 2, and Lamp. Calculate Fountain stack values after Bell 6, Lamp 99, Measurement 16, Cove upgrade 14, wallet-log, lucky-coin, and duck inputs are ready. This splits Fountain upgrade effects from its later stack valuation and avoids a false dependency cycle. If any input producer moves later, add a narrowly placed existing-style hook after that producer and before consumers; do not move unrelated stages.

Prepare Cove's character-local outputs only after the relevant character stats and targets are ready. Use the late `updateHoleCharacterCapabilities` stage after player-stat, secondary-stat, and skill-efficiency preparation only for operands available there; place any later dependency after its producer. Keep local DR, AFK, multikill, respawn, and pickup outputs distinct from ordinary account-wide APIs. Rebuild derived state on each update rather than stacking it. UI consumes prepared domain APIs and does not reproduce formulas or author descriptions.
