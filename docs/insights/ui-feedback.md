# UI direction

- **Reuse the actual pattern.** Inspect existing pages and their rendered layout. Match composition, spacing, alignment, and typography—not just component names.
- **Keep shared information above tabs.** Group related account values in compact summaries. Keep characters visible when they provide context across views.
- **Prefer dense, readable layouts.** Reduce repetition and unnecessary spacing. Keep important values easy to scan. Use verified game icons for recognition.
- **Make relationships obvious.** Keep each effect beside its level, requirement, and progress. Keep headers aligned with their values.
- **Show shared values once.** Combine related values, such as current/maximum. Move individual details into a useful summary tooltip.
- **Use tooltips for additional information.** Show contributors, locations, or detailed progress. Remove tooltips that repeat visible values.
- **Remove redundant copy.** Omit obvious headings, empty-state sentences, and labels already explained by values or visual state.
- **Keep explanations local and simple.** Place help beside the relevant content. Explain the player meaning, not the underlying mathematics.
- **Use established formatting and progress displays.** Reuse repository number formatters and bar styles. Verify caps and diminishing returns before displaying them.
- **Choose information for the player’s task.** Available backend fields are not a display checklist. Omit details that add no useful context.
- **Use competitor (IdleonToolbox) for content reference.** Learn which information and imagery help players. Take layout, navigation, and styling from our website.
- **Show comparisons when they matter.** Offer character selection when values differ meaningfully. Avoid controls that only repeat identical results.
- **Prefer useful game descriptions.** Use genuine game descriptions when they help the player’s task. Omit invented tutorials, lengthy mechanic explanations, and internal terminology.
- **Keep navigation local.** Avoid cross-content deep links. Preserve the user’s scroll position when changing tabs.
- **Keep inactive content readable.** Distinguish active content with restrained emphasis rather than heavy dimming. Distinguish locked, incomplete, and completed states.
- **Show the value of unobtained rewards.** Show what a source provides when obtained, not its current zero contribution.
